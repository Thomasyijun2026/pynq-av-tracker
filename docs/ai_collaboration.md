# 大模型协作与纠错记录

以下提示词和模型回答逐字摘自项目开发对话中双方可见的消息，按实际顺序节选。每组末尾的证据说明为发布时整理。文中角度、测试结果与后续计划保留当时的适用范围。

## 音频方向跳变与峰值选择

**用户提示词原文（2026-11-03）**

> 音频有问题，可能是算法上的问题，必须优先解决

**模型回答原文（1/3）**

> 13 段录音按板端实际窗口重算后，累加值、峰值和一致性检查全部逐项吻合。142.6° 那次跳变来自 MIC05–MIC08 的延迟峰跳到了接近 0 个采样点，与其他麦克风对矛盾；原程序已拒绝这个结果。接下来改进“各对独立取最大峰”的处理，让六组相关曲线共同约束方向，并保留歧义拒绝。

**模型回答原文（2/3）**

> 静止对照找到了一个明确的算法问题：三段播放录音的候选方向都在 76° 左右，却被 MIC01–MIC08 在 −13 个采样点的负相关旁瓣判成“峰值模糊”。这对麦克风的物理延迟上限约 9.5 个采样点，−13 不应参与方向候选比较。现在修正峰值搜索范围，并将负相关与正相关分开处理；几何和时间一致性检查继续保留。

**模型回答原文（3/3）**

> 回放同一份失败录音后，原因更明确了：将主峰搜索限制为各麦克风间距允许的正相关峰，方向从被拒绝的 103.47° 变为 75.07°，四个时间窗也全部一致。原有的矛盾录音仍被拒绝。我会把这项改动落实到 PL 的整窗和分段选峰中，再做新采样核验。

这组回复记录了按板端实际窗口重算、识别物理范围外的负相关旁瓣、再用同一失败录音复核的顺序。引用中的方向值属于当时的候选和回放结果。发布版的整数参考见 [音频验证](../validation/audio_reference.json)，适用场景和失效条件见 [整数参考技能](../skill/integer_reference/SKILL.md)。

## 初始化从当前视野改为整圈搜索

**用户提示词原文（2026-11-04）**

> 你初始化是要转摄像头的啊，你要转一圈然后找到那一帧画面的啊，你都没转你当然找不到，我没跟你说过初始化的工序吗，电脑发出声音，电脑放出视觉信号，麦克风和摄像头共同定位

**模型回答原文（1/2）**

> 代码里已确认，现入口写的是“仅检查当前可见屏幕”，所以一旦电脑不在镜头里就直接失败，舵机不会搜索。新入口会先完成整圈扫描，再选择识别质量最高的标识画面，转回该方向取新图确认；麦克风采集与扫描并行进行。这样才符合你要求的初始化工序。

**模型回答原文（2/2）**

> 整圈搜索已接入独立候选版本：扫描结束前不会建立映射，运动中的画面只用于确定返回方向，返回后还要用新拍的静止画面确认。界面报错也已改为保留板端的具体失败原因。接下来检查扫描顺序、音频重叠时间和失败后的资源释放，再安排实机验证。

用户指出初始化漏掉整圈搜索，随后把运动中的候选筛选和回转后的静止确认分开。一次已保存的完整初始化见 [实机结果节选](../validation/initialization_excerpt.json)，请求身份和资源管理见 [PYNQ 技能](../skill/pynq_lifecycle/SKILL.md)。

## 自动连接与人工初始化分开

**用户提示词原文（2026-11-04）**

> 还有，你这个软件我一打开他就要自动开始与板子连接而不是靠codex内部操作，在我一打开，电脑软件程序就得自动捕获板子信息与板子主动构成连接，同时定位服务通知也要立刻给到连上之后反复给，只有初始化时我们手动人工点来触发的

**模型回答原文（1/2）**

> 查到现有软件的问题了：它只查询定位服务端口，服务没有启动时，界面就把板子也显示成未连接。现在板子的系统接口可达，定位服务端口没有响应。
>
> 我正在增加独立的后台连接检测，让界面分别显示板子连接状态和定位服务状态，并持续自动更新。

**模型回答原文（2/2）**

> 自动连接部分已经写好：电脑程序会分别检测板子和定位服务，再把状态持续推送到界面。接下来验证断线重连和服务就绪提示，并确认打开软件、重连都不会自动发出初始化指令。

板卡连接与定位服务就绪分别显示，初始化保留人工触发。现有发布版本的操作和状态边界见 [复现说明](reproduce.md)。

## 实现时序与发布回归

FIR 初版布线后出现负时序裕量，随后对加法归约增加寄存流水并回归提交、复位和未完成事务。发布实现审查记录的 setup slack 为 +0.287 ns。早期 Windows 长路径问题通过使用 D 盘短构建目录处理。保存的工程产物与来源摘要见 [协作产物节选](../validation/materials/collaboration_artifacts.json)、[实现审查](../validation/implementation/review.json) 和 [来源记录](../validation/materials/provenance.json)。

人工确定实际装置、声源、触发工序与公开范围。模型负责诊断、源码与复现步骤整理。用户随后确认冻结已安装版本，发布时按 [复现交付技能](../skill/reproducible_delivery/SKILL.md) 校验逐文件内容。
